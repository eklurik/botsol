# Support Agent

Локальный прототип агента поддержки: сначала применяет детерминированные правила, затем безопасный risk-router, и только после этого использует OpenAI-compatible API для обычных вопросов. Деньги, безопасность, агрессия, юридические претензии и неизвестные случаи требуют оператора.

## Запуск

```bash
npm test
npm run test:regression
cp .env.example .env
```

В `.env` впишите новый ключ в `OPENAI_API_KEY`, затем запустите:

```bash
npm start
```

API: `POST /api/answer`.

`npm run test:regression` прогоняет все 24 кейса из `04_Расхождения_24_случая.json` через текущий rule engine и сравнивает production `rule` и `action`. Команда завершается с ошибкой, пока известные расхождения не исправлены.

Текущий результат gate: 23/24. `DIFF-05` оставлен красным намеренно: его `client_text` и `input_signals` полностью совпадают с `DIFF-04`, но production ожидает другое действие. Для исправления нужен дополнительный production-сигнал (например, история обращений, risk-флаг или полный необрезанный диалог); подмена решения по `case_id` была бы некорректной.

Денежные и рискованные обращения никогда не отправляются в модель: API возвращает `needsHuman: true` и `managerAction`, чтобы интерфейс показал передачу менеджеру. Обычные неясные сообщения получают уточняющий вопрос без эскалации; вопросы о начале поездки обрабатываются встроенным onboarding.
