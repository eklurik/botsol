## Контекст задачи в двух абзацах

У нас работает ИИ-оператор поддержки (самокаты и велосипеды, Киев). Он ведёт чат с клиентом,
но решения — завершить поездку, создать заявку технику, передать оператору, поставить запрос на
перерасчёт — принимаются **детерминированными правилами**, а не моделью. Правила отвечают в том
числе за деньги: штрафы за зоны, перерасчёты, возвраты.

Исторически правила жили в коде (сотни строк условий) и в промпте. Сейчас они переносятся в
редактируемые **таблицы решений**, чтобы старший оператор мог править их сам, а каждая правка
проверялась набором тестов до публикации. Задача подрядчика — **не построить систему с нуля, а
дожать существующую**: закрывать расхождения, расширять покрытие, довести до переключения прода.

## Про обезличивание данных

Файл `03` и тексты в `04` прошли обезличивание:

- **удалены полностью** (не входят в выгрузку): ID клиента, геокоординаты, баланс и суммы трат
  клиента, номер транспортного средства, счётчики штрафов, история поездок, признак телефона;
- **заменены псевдонимами**: диалог → `C0001`, клиент → `U0001`, ТС → `B0001`
  (псевдонимы стабильны внутри пакета, обратного соответствия наружу нет);
- **вычищено из текстов**: телефоны, e-mail, ссылки, номера карт/IBAN, длинные числовые
  идентификаторы, адреса (улица + дом), конструкции «меня зовут …».

Что осознанно **осталось** в текстах: суммы списаний и штрафов, названия зон, публичные ориентиры
(станции метро, ТРЦ) — без них случаи невозможно разобрать. Ориентиры не идентифицируют человека.

Просьба к получателям: пакет передан для оценки задачи, распространять его дальше не нужно.

## Про объём файла `03`

В папке лежит **выборка 97 записей из 1150** — по несколько случаев на каждое из 15 правил,
которые срабатывали за неделю. Полный файл (1150 решений) есть у нас и передаётся на этапе

Тексты обращений в выборке обрезаны до 140 символов.

## Структура записи в `03_Переписки_обезличено_выборка_97_из_1150.jsonl`

Одна строка — одно решение бота (формат JSON Lines):

```json
{
  "id": "C0014-2123",              // диалог + время
  "at": "2026-08-14T21:23:05Z",
  "dialog": "C0014",               // псевдоним диалога
  "client": "U0009",               // псевдоним клиента (сквозной: видно повторные обращения)
  "vehicle": "B0031",
  "client_text": "текст обращения (обезличенный, до 140 символов)",
  "signals": {
    "flags": ["ride_paid", "zone_forbidden"],   // маркеры, вычисленные системой ДО правила
    "snapshot": {
      "zone":  { "verdict": "black", "edgeDist": 2, "borderline": true },
      "ride":  { "amt": 80.25, "durSec": 741, "events": ["Unlock:Success"] },
      "iot":   { "motorUsed": null, "moved": false },
      "subscription": null, "activeRideCount": 1, "airraid": false
    }
  },
  "bot_decision": {
    "rule": "R14",                 // какое правило сработало
    "action": "escalate_refund",   // что сделал бот
    "executable": true,            // правило вообще может действовать само
    "executed": true               // действие выполнено или осталось в теневом режиме
  }
}
```

Пустые поля в выгрузке опущены: если ключа нет — значения не было.

Смысл ключевых полей: `flags` — состояние системы на момент обращения (есть активная поездка,
зона запрещена, списание было и т.п.); `snapshot.zone.verdict` — вердикт зоны
(`black` — чёрная, `red` — красная, `service`/`allowed` — разрешённая, `paid` — платная);
`edgeDist` — расстояние до границы зоны в метрах; `amt` — сумма списания за поездку.
